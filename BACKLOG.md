# Extension implementation backlog

Scope agreed October 22, 2026: preserve the existing hosted app and pinned frontend. Latest direction: implement the remaining areas in order, verify each, and pause only for questions that need a product or architecture decision. This is an implementation list; testing is part of each item, not a separate feature.

Current direction (desktop 0.9.0): target native canvas feature parity without any managed-package dependency, excluding saving, sharing and Upload Recall. The user confirmed Recall remains native-only. See NATIVE-PARITY.md for current coverage and differences.

1. **Browse and SOQL — implemented in 0.6.0.** Typed field filters, name/Case subject/exact-ID search, counts, sorting, paging, selected-record basket imports, SOQL previews, native query continuations, child relationship imports and a 500-record total import cap. See BROWSE-SOQL.md for retained limits.
2. **Import/export — implemented in 0.7.0.** Native CSV/JSON selection and save dialogs, inherited field mapping and linked-file import, record CSV and portable canvas JSON export. A CSV insert and JSON export/reimport round trip have UI coverage. Version 0.7.2 also enables External ID upsert uploads; this does not implement managed-package canvas saving.
3. **Remaining upload parity — implemented within desktop limits, 0.7.2.** Create/update/upsert groups use Composite Graph (up to 75 groups per request); deletions use the hosted child-first scheduler with direct DELETE requests. The 25-operation restriction is removed. Partial outcomes are journaled and uncertain writes stop subsequent requests. External ID matches are checked before and after native confirmation, with actual created/updated outcomes reconciled. Duplicate alerts have an explicit retry and native confirmation; blocking rules still apply. No managed package is used. The 500-record cap, no Bulk API ingestion, and uncertain-outcome recovery limitations remain (UPLOADS.md).
4. **Local recovery — implemented in 0.7.0.** AES-GCM snapshots scoped to org/user, encryption keys in VS Code SecretStorage, restore/discard prompt, encrypted host baselines and disconnect cleanup. One snapshot per identity; seven-day age limit checked on reopening. See DESKTOP-FEATURES.md for durability limits.
5. **Run Script — implemented in 0.7.0.** Existing restricted interpreter in a bounded local worker, cancellation, preview/apply and guarded Undo. No arbitrary JavaScript, network, filesystem or shell access.
6. **Migration — implemented in 0.8.0.** Same file-based workflow as the native app. Export for migration, connect to the destination, import and reconcile through the shared planner, then review and upload. Direct destination matching and metadata reads; no concurrent source connection or package required. Cancel preserves the active canvas. Source IDs, standalone references and sharing assignments are removed before applying.
7. **AI — deferred by user.** Keep disabled.
8. **MCP — deferred by user.** Keep disabled.
9. **Metadata/validation — aligned with the reviewed native scope.** Validation-rule definitions use direct Tooling API reads, with an explicit unavailable result when permissions prevent access. Lookup search excludes the current record before limiting results. Neither the reviewed native adapter nor desktop applies Salesforce lookup-filter rules during suggestions; Salesforce enforces them on upload. UI API unsupported layouts use accessible describe fallback.
10. **Desktop/release polish — partial.** Production connections enabled with native confirmation and clear labels. Safe native links to connected-org records and documentation, updated onboarding and local VSIX packaging. macOS/Linux/remote hosts remain unverified.

11. **0.8.0 corrections and desktop polish — implemented.** Capability checks for bulk editing, auto-fill and scripts; nullable circular draft references within atomic Graphs; record-link clipboard import without duplicate cards; org/user-scoped onboarding preferences; saving/sharing controls hidden and export clearly labeled. Pinned frontend refreshed through the canonical export tool without editing vendor files by hand.

12. **0.9.0 recovery and read hardening — implemented.** Fresh permissions before restoring, stale document/sequence rejection, connected panel serialization, startup/daily expiration cleanup, partial refresh, semi/anti-joins, 20,000-character queries, explicit capped results, and duplicate-write protection. Unknown writes are not automatically retried or reported as successful. See NATIVE-PARITY.md for limitations and verification.

Next: broader live acceptance across package-free and restricted-user orgs and supported desktop platforms; full window-restart acceptance; decide whether local browsable Activity belongs in this edition. The production decision remains explicit confirmation and clear labeling. No Marketplace release is authorized by this build.
